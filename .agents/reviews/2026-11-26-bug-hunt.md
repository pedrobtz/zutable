# zutable bug hunt, 2026-11-26

Commit `1990418` (the v0.1.0 release candidate, after Stage 19). The hunt
was the behaviour pass of Stage 20's critical review (#22).

- **Hunters:** 3, on Fable 5.2, run one at a time. Their slices were the R
  layer, lifecycle, and the C kernel and ownership.
- **Coordinator:** Opus 5.5.
- **Built here:** x86_64 macOS, R 4.6.2 with long double, and Apple clang 17.
  The standalone kernel and its C tests were built under ASan and UBSan, and
  the header as C++17.
- **Unverified:**
  - the R < 4.5 branch of `src/altrep.c`;
  - the double-accumulator reduce through R on an R without long double;
  - arm64;
  - the R shared object under sanitizers;
  - 2³¹ − 1 rows through R. That needs 16 GB or more, so the row-limit
    findings were run in C drivers only.

The probe scripts are in `2026-11-26-bug-hunt-probes/hunt-<n>/`. They expect
the pinned commit installed in `/tmp/zutable-hunt/lib`:

```sh
git archive 1990418 | tar -x -C /tmp/zutable-hunt/src
R CMD INSTALL --library=/tmp/zutable-hunt/lib /tmp/zutable-hunt/src
```

Run hunt-1 and hunt-2 scripts from their own directory, since they source
`pre.R`. Before filing, the coordinator re-ran every blocking and required
trigger against a fresh install.

filed the rest of the review's issues, #50 to #102. This section lists only
the findings the hunt reproduced; "hunt n" names the hunters that found

The code pass found #50 (string keys compared by CHARSXP pointer) and #60
(the reference join matches an int64 NA to 0). Both were re-run here.
Hunter 3's encoding probe (`hunt-3/p02_str_grp.R:19`) missed #50. It put an
unknown-encoded string in the same vector as a latin1 one, and the latin1
element forces the whole column to be translated, which hides the bug.

## Cross-cutting

- **The oracle shares the defect.** #55, #57 and #60 sit where the two
  executors share R code (values, row takes), or where the reference itself
  is wrong. The executor differential cannot see them. A second, independent
  oracle (DuckDB, a per-row loop) is what found them.
- **Marks and state that outlive their premise.** #56 (a sorted mark beside
  an NA), #52 (marks trusted from a file) and #61 (a one-shot flag that
  outlives the update it was set for) share a shape. Each records a fact
  about an object in a place the object's later life does not update.
  Candidate rule for `correctness.md`: *a cached fact about a value (a mark,
  a flag, a property) is set only where it holds for every later reader,
  and is validated wherever it enters from outside (unserialize, attributes,
  hand-made objects).*
- **Text as an intermediate for time.** #51, #54 and #58 all go through
  wall-clock or ISO text where arithmetic on the instant would be exact.

## Held: what was probed and stood

In summary; each hunter's report listed every probe.

- **Executors:** default against reference over every clause, 47 update
  statements and 72 join combinations, at 0 to 5000 rows, with NA, NaN, ±0
  and Inf. Zero-row tables everywhere. A hostile session (`OutDec`,
  `scipen`, `digits`, `warn = 2`, a non-UTC `TZ`).
- **Lifecycle:** aliases, `copy()`, split aliases after base replacement, and
  every write route on a frozen table other than #79. Failing blocks are
  atomic. A fork does not leak an update to the parent, and containers
  update in place. Serialization round trips. 21 ALTREP write routes against
  a plain vector. Executor switching mid-sequence.
- **Kernel:**
  - all six C tests and the 20,000-input fuzz smoke under ASan and UBSan;
    C++17 under ASan and UBSan;
  - `key_order`, `key_rank` and `key_sort` against `order(method =
    "radix")` and `rank()` over 17 generators × 21 sizes × both
    directions, plus 3000 multi-key orders across the 32- and 64-bit
    packing limits;
  - string order against a raw-byte oracle;
  - 600 random `grp()` calls;
  - the `grp(sort = TRUE)` rule at 10⁶ ± 1 rows;
  - `grp_reduce` against base R bit for bit, at 4095, 4096 and 4097 rows;
  - 1500 random joins and matches against brute force;
  - integer64 at ±(2⁶³ − 1).

## Not reached

- DuckDB was not used as an oracle by the hunters. It is the suite's.
- `timestamp("ns")` (`zutempo`).
- `explain()` through dplyr.
- Tables of 2³¹ rows through R.
- A real interrupt (SIGINT) inside a block.
- knitr's rendering of the print skip.
- Lazy tables, which come after 0.1.0.
- The ported-sorts test, which needs a network fetch.
- A libFuzzer run past the smoke.
- Non-UTF-8 locales for kernel string keys.

## Not reproduced, and by design

- **Not reproduced:** nothing; every reproduced trigger re-ran.
- **By design:** the D43 route behind #79 may be decided by design, so it
  is filed as a question. The NA-with-NaN reduce case in design-kernel §6.4
  is by design; the `Inf - Inf` case in #81 is not named there.
